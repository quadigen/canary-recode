---
title: Localization
description: Translate interface text using dictionaries and localization tables, and remember a player's language choice.
---

Use [LocalizationService](/docs/services/LocalizationService) to change the language of your interface without replacing every label's `Text` property. You supply the translations; the service looks up the matching string for the selected locale.

## Load a dictionary

Put this code in a LocalScript to select French for the local interface:

```lua
local localization = game:GetService("LocalizationService")

local loaded = localization:LoadTranslations("fr-fr", [[
{
    "Welcome": "Bienvenue",
    "Play": "Jouer",
    "Settings": "Paramètres"
}
]])

if loaded then
    localization:SetLocale("fr-fr")
end
```

If you set a TextLabel or TextButton to `"Play"`, it displays `"Jouer"` when French is selected. Reading its `Text` property still returns `"Play"`.

To translate a string yourself, call `Translate()`:

```lua
print(localization:Translate("Settings"))
```

The service returns the original string if it can't find a translation. Matching source strings is case-sensitive.

## Organize translations in an instance

Use a [LocalizationTable](/docs/LocalizationTable) when you want your translations to live alongside your project rather than in a JSON dictionary.

```lua
local localization = game:GetService("LocalizationService")
local translations = Instance.new("LocalizationTable", localization)

translations:SetEntries({
    {
        Key = "play",
        Source = "Play",
        Values = {
            ["fr-fr"] = "Jouer",
            ["de-de"] = "Spielen",
        },
    },
    {
        Key = "settings",
        Source = "Settings",
        Values = {
            ["fr-fr"] = "Paramètres",
            ["de-de"] = "Einstellungen",
        },
    },
})

localization:SetLocale("de-de")
print(localization:Translate("Play"))
```

Parent the table directly to the service so it can find the entries. Tables take precedence over loaded JSON dictionaries. You can also give an entry a context path to distinguish identical source strings used in different parts of the interface.

## Switch languages

```lua
local function selectLanguage(locale)
    if locale == "en-us" or locale == "fr-fr" or locale == "de-de" then
        localization:SetLocale(locale)
    end
end

selectLanguage("fr-fr")
```

The game locale is normalized to lowercase. An empty locale raises an error. Use `localization.RobloxLocaleId` to read the selected language. The optional second argument to `SetLocale()` changes `SystemLocaleId`; it isn't necessary when a player selects a language.

Existing labels and buttons update when the language changes. Editable text boxes aren't translated automatically.

## Remember the language

Locale settings and loaded dictionaries are held for the current session. Save a player's choice with [DataStoreService](/docs/services/DataStoreService) if you want to restore it on their next visit.

Validate the choice against your supported languages before saving it on the server. Send the saved preference to the client and apply it with `SetLocale()`. See [Saving player data](/docs/guides/saving-player-data) for the persistence workflow.

## What isn't translated automatically?

- The service doesn't detect the operating system's language yet. Both locale identifiers start at `en-us`.
- Number and date formatting, plural forms, and parameterized translation expressions need your own formatting code.
- Missing translations display the source string instead of falling back to another language's dictionary.
- There is no locale-change event. If your scripts produce their own translated strings, call your refresh function when changing the locale.

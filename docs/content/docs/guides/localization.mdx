---
title: Localization
description: Read and set locale identifiers, then drive your own translation table and interface text.
---

`LocalizationService` exposes two locale identifiers: the locale the game should present and the locale of the host system. It stores and reports those strings, but it doesn't translate anything by itself. There's no `LocalizationTable`, translator, or automatic UI translation in the current API.

That makes localization a small, explicit system in your game: choose a locale, set it on the service, and look up your own strings.

## Read the current locale

```lua
local LocalizationService = game:GetService("LocalizationService")

print(LocalizationService.RobloxLocaleId)  -- en-us
print(LocalizationService.SystemLocaleId)  -- en-us
```

Both default to `"en-us"`. Platform locale detection isn't wired up yet, so these values don't reflect the player's machine until something sets them. They also aren't persisted between runs.

Assigning `RobloxLocaleId` or `SystemLocaleId` directly has no effect. Use `SetLocale()`.

## Set a locale

```lua
LocalizationService:SetLocale("fr-fr", "fr-fr")

print(LocalizationService.RobloxLocaleId)  -- fr-fr
print(LocalizationService.SystemLocaleId)  -- fr-fr
```

Pass the second argument only when you want to update the system identifier too. An empty locale raises an error. The strings aren't validated beyond that: `"fr"`, `"fr-fr"`, and `"fr-FR"` are stored exactly as given, so normalize them yourself if you accept user input.

## Build a translation table

Keep strings in one module keyed by locale, with a shared fallback:

```lua
local strings = {
    ["en-us"] = {
        greeting = "Welcome",
        play = "Play",
        settings = "Settings",
    },
    ["fr-fr"] = {
        greeting = "Bienvenue",
        play = "Jouer",
        settings = "Paramètres",
    },
}

local function translate(key)
    local locale = LocalizationService.RobloxLocaleId
    local language = strings[locale] or strings["en-us"]
    return language[key] or key
end
```

Returning the key when a translation is missing makes a missing string visible instead of blank. If you prefer a louder failure, return a placeholder such as `"[missing: greeting]"`.

## Apply it to the interface

Create a refresh function and call it whenever the locale changes:

```lua
local Players = game:GetService("Players")
local playerGui = Players.LocalPlayer:WaitForChild("PlayerGui")
local greetingLabel = playerGui:WaitForChild("Greeting")

local function refresh()
    greetingLabel.Text = translate("greeting")
end

LocalizationService:SetLocale("fr-fr", "fr-fr")
refresh()
```

There's no locale-change event. If more than one script needs to react, give them one function to call or a `BindableEvent` that your settings screen fires after `SetLocale()`.

Keep the refresh cheap. Reading the locale and assigning `Text` is fine; rebuilding whole screens on every frame is not.

## Format numbers and dates yourself

The locale identifier doesn't change how `string.format()` or numbers render. If a language uses different decimal separators, grouping, or date order, format those values in your own helpers:

```lua
local formatters = {
    ["en-us"] = function(value)
        return string.format("%.1f", value)
    end,
    ["fr-fr"] = function(value)
        return (string.format("%.1f", value):gsub("%.", ","))
    end,
}

local function formatNumber(value)
    local locale = LocalizationService.RobloxLocaleId
    local format = formatters[locale] or formatters["en-us"]
    return format(value)
end
```

This is intentionally small. A full internationalization layer is your own module, not something the current service supplies.

## Let the player choose

A settings menu can offer a short list and set the locale directly:

```lua
local options = {
    { label = "English", locale = "en-us" },
    { label = "Français", locale = "fr-fr" },
}

local function chooseLocale(locale)
    LocalizationService:SetLocale(locale, locale)
    refresh()
end
```

The service lives on both server and client, but interface language is usually a client concern. Set it on the client that displays the text, unless you intentionally want a server-wide locale.

## Persist the choice

`SetLocale()` lasts for the session only. If the player should keep their language, save the locale string and apply it on join.

Server-side persistence with `DataStoreService`:

```lua
local data = {
    locale = "fr-fr",
}

saves:SetAsync(tostring(player.UserId), data)
```

On the client, read the saved value through whatever your game already replicates (a player attribute or a remote event), then call `SetLocale()` before building the interface. See [Saving player data](/docs/guides/saving-player-data) for the save/load flow.

Don't set the locale from an unvalidated client string without checking it against your supported list. Unknown locales will simply fall back to your default table, but a typo is easier to diagnose if you reject it explicitly.

## Common failures

| Symptom | Likely cause |
| --- | --- |
| Text never changes | The service stores identifiers; your code still has to read them and swap strings. |
| Assigning `RobloxLocaleId` does nothing | It's read-only. Call `SetLocale()`. |
| Locale resets on rejoin | Nothing persists it. Save the choice and apply it on join. |
| `SystemLocaleId` isn't the player's OS language | Detection isn't wired up; both fields start at `en-us`. |
| Some strings show raw keys | The key is missing from the active language and the fallback table. |
| A language switch updates one label only | There's no change event; call every refresh function from one place. |

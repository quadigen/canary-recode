---
title: VRService
description: Enable experimental OpenXR stereo rendering and read headset and controller poses.
---

`VRService` exposes the desktop OpenXR session to local scripts. VR is currently experimental and supported on Linux with Vulkan. A normal desktop launch does not require OpenXR or a headset.

## Running a VR game

On Arch Linux install the OpenXR SDK and loader, then install Monado from the AUR:

```bash
sudo pacman -S openxr
yay -S monado-git
```

If you are building Kinemium from source, rebuild after installing the headers:

```bash
just deps
just build
```

To simulate a headset and controllers without hardware, run Monado with its QWERTY driver in a separate terminal:

```bash
QWERTY_ENABLE=1 XRT_DEBUG_GUI=1 XRT_COMPOSITOR_FORCE_XCB=1 monado-service
```

Then run a saved map in singleplayer mode:

```bash
KINE_VR=1 XR_RUNTIME_JSON=/usr/share/openxr/1/openxr_monado.json ./build/kinemium --singleplayer --map path/to/game.kine
```

If your package installs the manifest elsewhere, use that path instead. The runtime and engine must choose the same Vulkan physical device. Keep the desktop window unminimized. The simulator's Qwerty System help panel describes its keyboard and mouse controls.

## Properties

| Property | Type | Access | Description |
| --- | --- | --- | --- |
| `VREnabled` | boolean | Read-only | Whether the OpenXR session is running. |
| `VRAvailable` | boolean | Read-only | Whether an OpenXR graphics session was successfully created in this launch. |

`UserInputService.VREnabled` reports the same running session state.

## Methods

| Signature | Description |
| --- | --- |
| `GetUserCFrame(userCFrame: Enum.UserCFrame): CFrame` | The last valid tracked pose in OpenXR local tracking space; identity if unavailable. |
| `GetUserCFrameEnabled(userCFrame: Enum.UserCFrame): boolean` | Whether a valid pose is available for this frame snapshot. |

Tracking poses are available for `Head`, `LeftHand`, `RightHand`, and `Floor` (if the runtime supports stage space). Hands represent controller grip poses, not individual fingers. One tracking meter is one engine world unit.

## Controller input and haptics

| Method | Return |
| --- | --- |
| `GetControllerState(hand: Enum.UserCFrame): table` | Current controller input. |
| `SetControllerHaptic(hand: Enum.UserCFrame, amplitude: number, seconds: number, frequency: number?): boolean` | Whether vibration was accepted. |

Use `Enum.UserCFrame.LeftHand` or `Enum.UserCFrame.RightHand` for these methods; other enum values raise an error.

### Controller state

| Field | Type | Description |
| --- | --- | --- |
| Active | boolean | At least one input action is active |
| Trigger | number | Analog value from 0 to 1, or select button as 0/1 |
| Grip | number | Analog squeeze or digital grip from 0 to 1 |
| Thumbstick | Vector2 | Stick or trackpad axes |
| TriggerAvailable | boolean | Trigger/select action active |
| GripAvailable | boolean | Squeeze action active |
| ThumbstickAvailable | boolean | Stick/trackpad action active |

Unavailable input reads as zero; use availability flags to distinguish this from a released control.
Input is sampled once per XR frame; scripts may read the previous completed sample.
The simple controller profile exposes select (mapped to Trigger) but not necessarily grip or stick actions.

### Haptics

Amplitude is between 0 and 1. Duration is specified in seconds (0 to 10).
The optional frequency is expressed in Hz; zero selects the runtime's default.
Zero amplitude or duration stops that hand's vibration. The call returns false
when the session is inactive/unfocused or the request is rejected. Actual
vibration depends on controller/runtime support.

```lua
local VR = game:GetService("VRService")
local RunService = game:GetService("RunService")
local hand = Enum.UserCFrame.RightHand
local held = false

RunService.RenderStepped:Connect(function()
    local state = VR:GetControllerState(hand)
    local pressed = state.TriggerAvailable and state.Trigger > 0.7
    if pressed and not held then
        VR:SetControllerHaptic(hand, 0.5, 0.1)
    end
    held = pressed
end)
```

This is an experimental Kinemium-specific input API. It does not yet dispatch
VR button events via UserInputService or ContextActionService.

## Example: visualize controller tracking

Place this code in a local script in a map. The two anchored parts follow controller grip poses relative to the base camera. Do not multiply the headset pose into the base camera yourself: the VR view already follows the headset.

```lua
local VR = game:GetService("VRService")
local RunService = game:GetService("RunService")

local hands = {
    {Enum.UserCFrame.LeftHand, Color3.fromRGB(70, 140, 255)},
    {Enum.UserCFrame.RightHand, Color3.fromRGB(255, 145, 55)},
}

for _, hand in ipairs(hands) do
    local part = Instance.new("Part")
    part.Size = Vector3.new(0.12, 0.12, 0.12)
    part.Color = hand[2]
    part.Anchored = true
    part.CanCollide = false
    part.Transparency = 1
    part.Parent = workspace
    hand[3] = part
end

RunService.RenderStepped:Connect(function()
    local camera = workspace.CurrentCamera
    if not camera then return end
    for _, hand in ipairs(hands) do
        local valid = VR.VREnabled and VR:GetUserCFrameEnabled(hand[1])
        hand[3].Transparency = valid and 0 or 1
        if valid then
            hand[3].CFrame = camera.CFrame * VR:GetUserCFrame(hand[1])
        end
    end
end)
```

## Limitations

VR is experimental. Physical headset compatibility and performance still need validation. Windows and mobile VR, skeletal hand tracking, and automatic locomotion aren't supported. VR startup failures fall back to normal desktop rendering.

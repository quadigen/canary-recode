---
title: LocalizationService
description: Read and change the locale identifiers the game reports.
---

`LocalizationService` exposes the game's locale as two string identifiers: the locale the experience should present, and the locale of the machine it's running on. Today it stores those values and reports them back. It doesn't translate text on its own.

## Getting started

```lua
local LocalizationService = game:GetService("LocalizationService")

print(LocalizationService.RobloxLocaleId)  -- en-us
print(LocalizationService.SystemLocaleId)  -- en-us
```

## Properties

| Property | Type | Access | Default | Description |
| --- | --- | --- | --- | --- |
| `RobloxLocaleId` | `string` | Read-only | `"en-us"` | Locale identifier the game should use. |
| `SystemLocaleId` | `string` | Read-only | `"en-us"` | Locale identifier of the host system. |

Both properties start as `"en-us"`, even if the operating system is set to something else. Platform locale detection isn't wired up yet, so don't rely on these values to reflect the player's machine until you set them.

Assigning to either property has no effect. Use `SetLocale()` instead.

## Methods

### SetLocale

```lua
SetLocale(locale: string, systemLocale: string?): ()
```

Sets `RobloxLocaleId` to `locale`. If you pass `systemLocale`, it also sets `SystemLocaleId`; otherwise the system identifier keeps its previous value.

```lua
LocalizationService:SetLocale("fr-fr", "fr-fr")

print(LocalizationService.RobloxLocaleId)  -- fr-fr
print(LocalizationService.SystemLocaleId)  -- fr-fr
```

An empty `locale` raises `locale must not be empty`. The strings aren't validated beyond that: `"fr-fr"`, `"fr"`, and `"fr-FR"` are all stored as given, with no normalization.

The method returns nothing.

## Notes

- Changing the locale doesn't change any text by itself. There's no verified `LocalizationTable`, translator, or automatic UI translation in the current API, so you'll need to read these identifiers and pick your own strings.
- There's no event for locale changes. If other code needs to know, call it from one place and pass the value along.
- Values set here last for the session. Nothing persists them to disk or across runs.
